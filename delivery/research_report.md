| 维度 | 内容 | 置信度 |

| 产品定位 | 「Hyper-Personalized, Real-Time Horoscopes」：用 NASA 星历数据 + 自然语言引擎算法化生成个人星盘与关系解读的占星 App | 已核实（官网首页文案） |

| 架构特点 | 数据层（JPL Horizons 星历，经第三方评测转述）与解释层（语言模型生成文本）分离；每日内容由 transit 数据触发 | 推断（来源：第三方评测对架构的转述，官方未公布实现细节） |
| 部署形态 | 闭源 SaaS，Native App + Web 体验 | 已核实 |
| 集成方式 | 无公开 API / SDK，仅终端用户使用 | 已核实 |
| 定价模式 | Freemium：核心每日体验免费；订阅档解锁扩展解读与无限合盘。第三方口径存在冲突（一说约 2.99 美元 / 月，一说 8.99 美元 / 月及一次性解锁至 11.99 美元），以商店实时价格为准 | 推断（两个第三方来源互相冲突，列入 U-01 待确认） |
| 优势 | 数据严谨性与叙事分层结合；免费档完整可用；视觉与品牌一致性极强，驱动自传播 | 综合归纳 |
| 局限 | 解读深度受「箴言式」文风限制；隐私是公认弱点（出生数据 + 好友图谱收集面大）；解读生成逻辑不透明 | 已核实（第三方评测一致指出）+ 推断 |
| 对本项目的参考价值 | 证明「严谨数据输入 + 有边界解释输出 + 免费档完整」是同类头部产品的共识结构；其隐私收集面是 STARVEIL「本地优先、数据不出本机」路线的反面参照 | 推断 |

> **四段式「对比」段**。在 §2 的事实基础上建立对比矩阵，赋予权重并打分。评分对象是「该标杆作为 STARVEIL 痛点分析参照系的可借鉴价值」，不是对标杆产品本身的优劣裁决。

### 3.1 对比矩阵

> **每行权重之和 = 1.00**。

| 评估维度 | 权重 | 权重理由 | B1 得分 | B2 得分 | B3 得分 | B4 得分 |
| --- | --- | --- | --- | --- | --- | --- |
| 场景契合度 | 0.30 | 本阶段唯一目的是用标杆解释 STARVEIL 痛点；场景错位即无解释力，故权重最高 | 4 | 5 | 5 | 4 |
| 技术成熟度 | 0.20 | 痛点归因需要「业界已验证」的实践背书，成熟度决定证据强度 | 5 | 4 | 3 | 2 |
| 集成难度（反向） | 0.15 | 开源可读性决定 STARVEIL 能逐行比对多少实现细节；闭源黑箱只能借鉴产品策略 | 3 | 3 | 5 | 4 |

**评分标尺**：每项 1~5 分，1 = 严重不符合，3 = 基本满足但存在明显局限，5 = 完美契合。

**加权计算明细**（便于人工审核复核）：

- B1 Co–Star：4×0.30 + 5×0.20 + 3×0.15 + 3×0.15 + 4×0.20 = 1.20 + 1.00 + 0.45 + 0.45 + 0.80 = **3.90**
- B2 TowerStar：5×0.30 + 4×0.20 + 3×0.15 + 3×0.15 + 3×0.20 = 1.50 + 0.80 + 0.45 + 0.45 + 0.60 = **3.80**
- B3 Tarot Oracle：5×0.30 + 3×0.20 + 5×0.15 + 5×0.15 + 3×0.20 = 1.50 + 0.60 + 0.75 + 0.75 + 0.60 = **4.20**
- B4 Mystic Tarot：4×0.30 + 2×0.20 + 4×0.15 + 5×0.15 + 4×0.20 = 1.20 + 0.40 + 0.60 + 0.75 + 0.80 = **3.75**

**单项打分依据摘要**：

- B1 场景契合度 4：同为 AI 灵性解读产品且有个性化输入，但领域是占星而非塔罗、形态是 Native App 而非 Web 单页（SR-01）。
- B1 合规可控性 4：商业公司运营、免费档完整；但第三方一致指出其隐私收集面大（出生数据 + 好友图谱），恰是 STARVEIL 本地优先路线的反例（SR-02/SR-03）。
- B2 场景契合度 5：AI 塔罗 + 多牌阵 + 追问 + 仪式动画，与 STARVEIL 功能清单几乎同构（SR-04）。
- B2 合规可控性 3：无任何公开合规 / 边界设计信息，且同样处于「AI 算命」监管敞口下（SR-04；SR-14）。
- B3 集成难度 5：同栈开源、架构分层文档清晰，可逐行对照（SR-05）。
- B3 合规可控性 3：本地自托管、密钥自管是加分；但 `VITE_` 前缀密钥暴露是明确缺陷，对照 D1 §DeepSeek 配置的安全约束（SR-05；D1）。
- B4 技术成熟度 2：个人 demo，无测试、无评测、无性能度量说明（SR-06）。

### 3.2 评分结论

- **优先借鉴**：B3 Tarot Oracle — 适用度评分 **4.20**，理由：场景契合度 5/5 且集成难度 5/5，是唯一可逐行对照的同栈同类开源实现；其「结构化 JSON 约束 + 本地兜底 + 追问继承上下文」三件事与 STARVEIL 已有设计互为印证，其密钥前缀反例则印证 STARVEIL 服务端密钥约束的价值。虽然技术成熟度仅 3/5（无测试无评测），但作为工程对照基线的不对称优势最大。
- **部分借鉴**：B1 Co–Star — 适用度评分 **3.90**，借鉴点：数据输入严谨性与解释输出分离的产品结构、免费档完整可用的商业模式、编辑监督式的内容理念（SR-01/SR-03）；不借鉴的部分：闭源社交图谱与高隐私收集面的数据策略（与 STARVEIL 本地优先方向相反）。
- **部分借鉴**：B2 TowerStar — 适用度评分 **3.80**，借鉴点：同类产品的功能基线（问题驱动牌阵、逆位处理、情绪记录、版本化迭代节奏），用于校验 STARVEIL 功能清单的结构性缺口（SR-04）；不借鉴的部分：黑箱解读管线无法作为质量保障证据，社区功能带来的数据收集面暂不适合本地优先产品。
- **不借鉴（否决）**：B4 Mystic Tarot — 适用度评分 **3.75**，否决理由：完全缺失 AI 解读与质量保障维度（对 STARVEIL 解读链路痛点零解释力），技术成熟度 2/5 为全场最低，且手势模式引入摄像头权限这一与沉浸体验无关的额外门槛；仅保留其扇形牌带交互作为体验参考，不作为改造主线参照系。
