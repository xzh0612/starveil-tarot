# Starveil Agent (Python)

The reading agent for 星幕塔罗 STARVEIL, ported from the original Node ESM
implementation in `frontend/server-js-reference/`.

The port is a **behaviour-preserving translation**. It is not a rewrite and it is
not an optimisation pass: every validation gate, error message, character budget
and ordering rule must produce the same result as the JavaScript original.

## Layout

| File | Ported from | Contains |
|---|---|---|
| `deck.py` | `src/domain.js`, `src/data/*` | 78-card deck, 9 spreads, guide corpus loader |
| `reading_rag.py` | `server-js-reference/reading-rag.mjs` | corpus, intent routing, evidence retrieval, output validation |
| `spread_recommendations.py` | `server-js-reference/spread-recommendations.mjs` | local + AI spread recommendation |
| `readings.py` | `server-js-reference/readings.mjs` | prompt assembly, provider call, repair loop |
| `reading_eval.py` | `server-js-reference/reading-eval.mjs` | offline retrieval / prompt / reading evaluation |
| `app.py` | `server-js-reference/readings.mjs` (middleware) | FastAPI HTTP surface |

## Naming convention

**Python identifiers are snake_case. Every JSON key and every user-visible
string stays byte-identical to the JavaScript original.**

| JavaScript | Python |
|---|---|
| `analyzeReadingQuestion` | `analyze_reading_question` |
| `retrieveReadingEvidence` | `retrieve_reading_evidence` |
| `MEMORY_RETRIEVAL_VERSION` | `MEMORY_RETRIEVAL_VERSION` |

The camelCase keys inside returned dicts are part of the HTTP contract with the
React client (`promptBudget.historySelectedChars`, `evidenceMeta.coverageStatus`,
…) and must not be renamed.

Prompt text, error messages, fence markers (`<starveil_context>`,
`<starveil_history>`, `<starveil_turn>`) and version strings must be copied
character for character, including full-width punctuation.

## Data access

`deck.py` is the only module that touches data files. It exposes:

```python
DECK_VERSION          # 'rws-1909-v1'
GUIDE_VERSION         # 'rws-editorial-2026-09-12'
CARDS                 # list[dict], 78 entries, insertion-ordered
CARD_BY_ID            # dict[str, dict]
SPREADS               # list[dict], 9 entries, insertion-ordered
CARD_GUIDES           # dict[str, dict] with symbolism/upright/reversed/relationships/work/question
CARD_REFERENCES       # parsed src/data/card-references.json
```

Sources: `backend/data/starveil-domain.json` (generated by
`scripts/export-domain-json.mjs`) and `src/data/card-references.json` (already
JSON, read in place so the frontend stays the single source of truth).

## Translation rules

These are the JavaScript behaviours that silently diverge when translated
carelessly. Apply them deliberately.

| JavaScript | Python | Why it matters |
|---|---|---|
| `a ?? b` | `a if a is not None else b` | `??` only falls back on null/undefined, **not** on `0` or `''` |
| `a \|\| b` | `a or b` | falls back on any falsy value |
| `String(x ?? '')` | `'' if x is None else str(x)` | keeps `0` and `False` |
| `JSON.stringify(v)` | `json.dumps(v, ensure_ascii=False, separators=(',', ':'))` | JS does not escape non-ASCII and emits no spaces; prompt bytes depend on this |
| `[...new Set(a)]` | `list(dict.fromkeys(a))` | both preserve first-seen order |
| `Object.hasOwn(o,k)` | `k in o` | |
| `o?.k` | `o.get('k')` on dicts | |
| `arr.slice(-n)` | `arr[-n:]` | |
| `arr.slice(0,n)` | `arr[:n]` | |
| `arr.at(-1)` | `arr[-1]` | |
| `sorted(a,b)=>a-b` | `sorted(a, key=...)` | Python's sort is stable, and so is modern V8's |
| `s.replaceAll('<','\u003c')` | `s.replace('<','\u003c')` | Python's `str.replace` already replaces all |
| `s.replace(re,'x')` | `re.sub(...)` | |
| `/re/.test(s)` | `re.search(...)` | `.test` is a search, not an anchor |
| `s.split(re)` | `re.split(...)` | |
| `[\s\S]` | `[\s\S]` | works unchanged; no `re.DOTALL` needed |
| `/i` | `re.IGNORECASE` | `/u` needs no Python flag |
| `/g` | replace-all default | `re.sub` / `re.findall` are already global |
| `Number.isFinite(x)` | `isinstance(x,(int,float)) and not isinstance(x,bool) and math.isfinite(x)` | |
| `1_000` numeric separators | `1_000` works, or write plain digits | |
| `Math.min/max` | `min/max` | |
| `encodeURIComponent` | `urllib.parse.quote` | |

### Regex notes

The original never uses `\w`, `\b` or `\B`, so the usual ASCII-vs-Unicode word
boundary trap does not apply. `\d` appears a handful of times; JavaScript's `\d`
is ASCII-only, so keep the surrounding patterns anchored to ASCII context rather
than relying on Python's Unicode `\d`.

## Testing the HTTP surface

The original JavaScript tests injected a fake provider through the middleware's
`fetchImpl`. The Python equivalent injects a transport into `ReadingService`, and
talks to a real server:

```python
from backend.app import create_app
from backend.readings import ReadingService

def fake_transport(*, url, headers, body, timeout_seconds):
    """Stands in for `fetchImpl`; returns (http status, body text)."""
    return 401, "upstream auth failure"

service = ReadingService(api_key="test-secret", transport=fake_transport)
app = create_app(service=service)
```

A transport is any callable accepting the keyword arguments `url`, `headers`,
`body` and `timeout_seconds`, returning a `(status_code, response_text)` tuple.
A `(200, json_text)` pair stands in for a successful provider reply; any other
status becomes an `{"kind": "http", ...}` result the service maps to an error
envelope. Raising `TimeoutError` (or `socket.timeout`) simulates the abort path
that yields `504 provider_timeout`.

`ReadingService.semantic_reranker` is injected the same way and must be an
`async` callable.

## Non-negotiables

1. **No behaviour changes.** No extra validation, no reordered checks, no
   "nicer" error messages, no performance shortcuts that change output.
2. **Validation order is observable.** Callers depend on *which* error surfaces
   first, so keep the original order of `throw` / raise statements.
3. **Character budgets are exact.** `READING_PROMPT_CHAR_LIMIT=56_000`,
   `MIN_HISTORY_CHAR_BUDGET=4_000`, `HISTORY_TRUNCATION_MARKER='…[中段历史已省略]…'`.
4. **Determinism.** Retrieval, ranking and budgeting must return identical
   sequences for identical input, including tie-breaking.
